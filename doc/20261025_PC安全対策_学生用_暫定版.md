# スタックチャン演習：開発PCの安全対策（学生用・暫定版）

作成日：2026-10-25。先生の本体での確認はまだ終わっていません。
**この文書の配布だけでは、ビルドや音声対話の再開許可にはなりません。先生の連絡を待ってください。**

## 1．何をするか

開発ツールが偽のダウンロード先へ接続しないよう、GitやPlatformIOの証明書情報を更新・確認します。
PCを複数使う人はPCごとに対策します。2人1組でも両方のPCを使うなら両方が対象です。
ファイルを削除したり、APIキーを提出したりする必要はありません。

## 2．再開の連絡まで

| 作業 | 暫定的な扱い |
|---|---|
| コード・性格設定の編集、ローカル保存 | 続けてよい |
| 資料閲覧・レポート作成 | 続けてよい |
| OS・ブラウザの通常の公式更新 | 実施してよい |
| この文書で指定する安全対策と公開先の接続検査 | 実施してよい |
| PlatformIOのBuild／Upload／Upload Filesystem | 待つ |
| Gitのclone／pull／fetch／push | 待つ（指定の公開先の検査だけ例外） |
| 部品の新規追加、通常のライブラリ更新 | 待つ |
| スタックチャンのオンライン音声対話 | 待つ |

ビルドでは不足している部品が自動取得されることがあるため、今回はビルドも一時停止します。

## 3．最初に先生へ伝えること

- PCの台数と、それぞれのOS（Windows／Mac／Linux）。
- 学校管理PC等で、自分で更新できるか。
- PlatformIO以外にPython・Conda・Node.js・WSL等を開発で使っているか。

APIキー・パスワード・設定ファイルは提出しません。

## 4．Windowsの手順

[共通のPC対策手順](20261025_PCごとの安全対策_先生用.md)の**手順2〜7**を順に行います。
文書名は「先生用」ですが、この部分は学生も同じです。長い更新コマンドの食い違いを防ぐため、共通手順を使います。

1. Windows・ブラウザ・VS Codeを更新。
2. Git for Windowsを修正版へ更新。
3. pio system infoでPlatformIOが使うPythonを確認。
4. そのPythonのpip・certifiを更新。
5. 通常接続と、問題の証明書の拒否を確認。

Pythonが3.9以下、更新失敗、検査にSTOPが出る、判断できない場合はそこで止めて先生へ相談します。

**してはいけないこと**

- 証明書エラーを無視する設定にする（--insecure、-k、--trusted-host、sslVerify false等）。
- platformio.iniのライブラリ版・書き込み速度を変更する。
- pio pkg updateを実行する。
- .pioやPython環境を削除して最初から入れ直す。
- 設定ファイルやAPIキーをチャットへ貼る。

## 5．Mac・Linuxの場合

Macの人は[Mac学生向けの安全対策マニュアル](20261025_PC安全対策_Mac学生用.md)を使います。Windows用コマンドは使いません。
Mac版にも、更新・Python対策・接続検査と、問題が残る場合に先生と行う暫定対策を載せています。Mac実機では未検証なので、先生が最初の少数例で結果を確認します。
LinuxはOS・ブラウザを公式更新し、OSの版とPlatformIOのPython情報を先生へ伝え、個別の手順を待ってください。

## 6．完了報告

次の項目だけを提出します。パス中のユーザー名は伏せて構いません。

~~~text
PCの呼び名：
OS：
Gitの版：
PlatformIOのPythonの版：
pipの版：
certifiの版：
Windows curl：通常接続OK／問題の2経路拒否OK／未確認
Git：通常接続OK／問題の2経路拒否OK／未確認
PlatformIO Python：3行PASS／STOP／未確認
ほかに使う開発環境：なし／あり（名前）
困っている点：
~~~

PCの対策が済んでも本体のプログラムは自動では直りません。先生から確認済みの修正版と書き込みの指示が出るまで待ちます。
以前ビルドや会話をしたことだけで、被害があったとは判断しません。まず更新・確認を行います。
