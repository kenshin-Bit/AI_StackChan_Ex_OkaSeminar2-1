# スタックチャン演習：MacのPC安全対策（学生用・暫定版）

作成日：2026-10-25。対象：既にVS Code・Git・PlatformIOが入ったMac。
Intel／Appleシリコン（Mシリーズ）共通です。WindowsのPowerShellコマンドは使いません。
この文書はWindows上で作成し、記法を確認しています。Mac実機では未検証です。まず先生が少数のMacで結果を確認してください。

**PCの対策完了と本体の修正は別です。先生から再開の連絡があるまでは、ビルド・書き込み・本体のオンライン音声対話を待ってください。**

## 1．作業の範囲と順序

1. macOS・ブラウザ・VS Codeを公式機能で更新する。
2. ターミナルを開き、実際に使うGit・curl・PlatformIOのPythonの場所を確認する。
3. PlatformIOのPythonのpip・certifiを更新する。
4. 通常接続と問題の証明書の拒否を検査する。
5. 問題が残るMacは、先生と付録の対策を確認し、再検査する。
6. 結果を先生へ報告する。

Macを複数使う場合は1台ずつ行います。別アカウント・別Python環境も追加確認が必要です。
コード・性格設定の編集、ローカル保存、資料閲覧・レポート作成は続けられます。
通常のGit送受信、部品の追加・更新、PlatformIOのBuild・Upload・Upload Filesystemは再開連絡まで待ちます。
以下に指定した安全対策の更新と公開先の接続検査は実施できます。

## 2．macOS・ブラウザ・VS Codeを更新する

1. 作業中のファイルを保存する。
2. Appleメニュー→「システム設定」→「一般」→「ソフトウェアアップデート」で通常の更新を適用する。画面が違う場合はシステム設定で「ソフトウェアアップデート」を検索する。
3. 求められたら再起動する。
4. Chromeならメニューの「Google Chromeについて」で更新して再起動する。SafariはmacOSの更新で更新する。
5. VS Codeもメニュー内の更新確認から公式更新を適用する。

学校管理のMacや管理者権限がない場合は先生へ相談します。
Appleはブラウザ等への対策と、一部のターミナルツールへの対策を区別しています。OSを更新しただけでは完了と判断せず、後の検査を行います。

## 3．ターミナルと使用中のツールを確認する

Command＋スペースでSpotlightを開き、「ターミナル」と入力して起動します。
以後、同じターミナル画面で進めます。コマンドを貼ったらReturnを押します。
「%」や「$」という入力欄の印は、コマンドに含めません。

~~~sh
sw_vers -productVersion
uname -m
command -v git
git --version
command -v curl
curl --version
~~~

記録するのは、macOSの版、CPU、Gitとcurlの場所・版です。
代表的な場所：

| 場所 | 意味・扱い |
|---|---|
| /usr/bin/git、/usr/bin/curl | Mac標準／Appleの開発ツール。手順6で検査する |
| /opt/homebrew/...、/usr/local/... | Homebrew等の可能性。標準ツールと別に検査する |
| その他・複数ある | 先生へ場所を伝えて確認する |

Gitのインストール画面が出る、Gitがない、Homebrew等の更新が必要な場合は、勝手に別のGitを追加せず相談します。
Mac標準Gitの版を、Windows向けの「2.56.0.windows.3」と比較する必要はありません。

## 4．PlatformIOのPythonを確認する

VS CodeでCommand＋Shift＋Pを押し、「PlatformIO: Open PlatformIO Core CLI」を検索して開きます。
または左のPlatformIOアイコン→Quick Access→Miscellaneous→PlatformIO Core CLIを開きます。

~~~sh
pio system info
~~~

表示の「Python」の版と「Python Executable」のパスを控えます。ビルドはしません。
例えば /Users/自分の名前/.platformio/penv/bin/python です。
**Pythonが3.10以上なら続けます。3.9以下、実行できない場合はそこで止めて先生へ相談します。**

先ほどのターミナル.appへ戻り、次を実行します。入力待ちになったら、自分のPython Executableのパスを引用符なしで貼り付けます。

~~~sh
printf 'Python Executableのパスを引用符なしで貼り付けてReturn: '
IFS= read -r pio_python
"$pio_python" --version
"$pio_python" -m pip --version
~~~

パスを変数pio_pythonへ入れています。例のパスをそのまま使わないでください。
この画面を閉じたら、この変数設定からやり直します。Pythonにsudoは付けません。

## 5．そのPythonのpip・certifiを更新する

pipはPythonの部品を取得する道具、certifiは接続先の確認用証明書一覧です。

### 5-1．pipが26.2.2未満の場合だけ更新する

26.2.2以上なら、次の長いコマンドは飛ばして5-2へ進みます。
古い場合は、次を1行丸ごと貼り付けます。末尾のSHA-256でファイルの一致を検査します。

~~~sh
"$pio_python" -m pip install "pip @ https://files.pythonhosted.org/packages/3f/06/3e4420302363fbb71be3c7f35ce042f54bfca330e3e66b3a2e3c4cca579f/pip-26.2.2-py3-none-any.whl#sha256=fd7f4dfa8190e014013b9f08f3e973f4e4c26ffd179a204895533a7254813a70"
~~~

ハッシュ不一致・証明書エラー・権限エラーが出たら止めます。--trusted-hostを付けたり、sudoで無理に通したりしません。

### 5-2．certifiを更新・確認する

pipが基準を満たしていることを確認してから実行します。

~~~sh
"$pio_python" -m pip install --upgrade "certifi>=2026.10.19"
"$pio_python" -m pip --version
"$pio_python" -c "import certifi; print(certifi.__version__)"
~~~

合格：pip 26.2.2以上、certifi 2026.10.19以上。
別のPython・Conda・Node.js・Docker等も開発で使う場合は別途対策が必要です。PlatformIO側の更新だけで他の環境は直りません。

## 6．通常の通信と、問題の証明書の拒否を確認する

公開先の検査です。APIキー・パスワード・GitHubトークンは入力しません。
問題の証明書を使う代表的な2経路を検査します。全攻撃の網羅試験ではありません。
時間切れ・名前解決失敗は「未確認」です。証明書の拒否と区別します。

### 6-1．Mac標準のcurl

まず正常なサイトからHTTP応答が返ることを確認します。

~~~sh
/usr/bin/curl -I https://github.com/
~~~

HTTP/2 200等のHTTP応答が合格です。続けて次を実行します。

~~~sh
/usr/bin/curl https://dv-g3b-emudhra.we-have-a-problem.com/
/usr/bin/curl https://dv-g3b-aaa-emudhra.we-have-a-problem.com/
~~~

この2つは、証明書を信頼できない、失効している等の証明書エラーで失敗するのが合格です。
ページ本文を取得できた場合は、まだ問題の証明書を受け入れています。先生と付録を確認します。
-k、--insecureを付けてはいけません。

手順3でcurlの場所が/usr/bin/curl以外だった人は、上の3コマンドの/usr/bin/curlをcurlにして、実際に使うcurlでも検査します。
標準curlだけが合格しても、別のcurlは対策済みとは扱いません。

### 6-2．実際に使うGit

Finderで授業のプロジェクトフォルダーを開きます。
ターミナルで「cd 」と入力し、firmwareの一つ上のプロジェクトフォルダーをドラッグしてReturnを押します。
次に実行します。

~~~sh
git ls-remote https://github.com/git/git.git HEAD
~~~

長い英数字とHEADの表示が、通常接続の合格です。
ログインを求められたら入力せず相談します。続けて次を実行します。

~~~sh
git ls-remote https://dv-g3b-emudhra.we-have-a-problem.com/ HEAD
git ls-remote https://dv-g3b-aaa-emudhra.we-have-a-problem.com/ HEAD
~~~

この2つは証明書エラーで失敗するのが合格です。
repository not foundやHTTP 404だけの場合は、証明書を拒否した証拠ではありません。

Gitが/usr/bin/gitの場合に問題が残れば付録へ進みます。
Homebrew等のGitで問題が残る場合は、付録のシステムファイル変更だけでは直らないことがあります。先生へGitの場所と結果を伝え、更新元の公式対策で個別に確認します。
この文書ではHomebrewの新規導入や、一律のbrew update／upgradeを指示しません。更新の通信自体が未対策のツールを通る場合があるためです。

### 6-3．PlatformIOのPythonが実際に使う通信

以下を一塊で、pio_pythonを設定したターミナルに貼り付けます。

~~~sh
"$pio_python" - <<'PY'
import requests
urls = [
    ('https://github.com/', False),
    ('https://dv-g3b-emudhra.we-have-a-problem.com/', True),
    ('https://dv-g3b-aaa-emudhra.we-have-a-problem.com/', True),
]
passed = 0
for url, must_reject in urls:
    try:
        r = requests.get(url, timeout=20, allow_redirects=False)
    except requests.exceptions.SSLError as exc:
        detail = str(exc).lower().replace('_', ' ')
        ok = must_reject and 'certificate verify failed' in detail
        result = 'certificate rejected' if ok else 'other TLS error: not confirmed'
    except requests.exceptions.RequestException:
        ok = False
        result = 'network error: not confirmed'
    else:
        ok = not must_reject and 200 <= r.status_code < 400
        result = 'HTTP ' + str(r.status_code)
        r.close()
    print(('PASS' if ok else 'STOP'), url, result)
    passed += int(ok)
raise SystemExit(0 if passed == len(urls) else 1)
PY
~~~

3行ともPASSなら合格です。STOP、requestsがない等のエラーは未確認です。先生へ知らせます。
証明書確認を無効にする設定や、環境の削除で回避しません。

パス中の自分の名前は伏せて構いません。
SC_SecConfig.yaml、APIキー、Wi-Fiパスワード、生のシリアルログは提出しません。
先生が各項目を確認し、PCでのビルド再開と本体での音声対話再開を別々に案内します。
PCの更新だけで本体のプログラムは変わりません。

## 付録A．標準curl・標準Gitに問題が残る場合（先生・管理者と実施）

### A-1．何を変更するか

Appleは、/etc/ssl/cert.pemを使う一部のコマンド向けに、影響するルート証明書を一覧から除く暫定策を案内しています。
下記はその考え方に沿った授業用の手順です。**Apple公式コマンドの逐語転載ではありません。**
このシステムファイルを使う他のツールにも影響します。正常な一部のサイトが接続できなくなる可能性があります。
Macのキーチェーンから証明書を削除する操作ではありません。独自の証明書一覧を持つアプリには別の対策が必要です。

学生だけで実行せず、先生・管理者と対象Macを確認して進めます。大学管理Macでは管理者が対応します。
最初に[Apple公式案内](https://support.apple.com/en-us/149555)の最新内容を確認してください。公式の修正更新が利用でき、手順6の検査に通るなら手動変更は不要です。

### A-2．バックアップ

ターミナルで実行します。sudoで求められるのはMacのログインパスワードです。入力中に文字は表示されません。パスワードを他人へ伝える必要はありません。
同名バックアップが既にある場合は上書きしません。

~~~sh
if [ ! -e /etc/ssl/cert.pem.stackchan-20261025.bak ]; then
    sudo cp -p /etc/ssl/cert.pem /etc/ssl/cert.pem.stackchan-20261025.bak
fi
~~~

エラーなら止めます。続けて現在のファイルを一覧化します。

~~~sh
/usr/bin/openssl crl2pkcs7 -nocrl -certfile /etc/ssl/cert.pem | /usr/bin/openssl pkcs7 -print_certs -noout | /usr/bin/grep -E 'emSign ECC Root CA - G3|AAA Certificate Services'
~~~

該当名が出る場合は次へ進みます。該当なしと解析エラーは別です。何も出なくてもエラー表示があれば止めます。
既に両方がなくても手順6で受け入れる場合は、別の証明書一覧・設定が使われている可能性があるため、以下を繰り返さず個別調査します。

### A-3．2経路の信頼元を一覧から除く

emSign側だけ除いても、AAA Certificate Servicesを経由する別経路が残ります。
次はApple形式の説明行で2つの証明書区間を除外し、一時ファイルが空でないときだけ置き換えます。
同じ内容をキーチェーンや他のファイルへ適用しません。

~~~sh
tls_tmp=$(mktemp)
if /usr/bin/awk \
    -v first='=== /C=IN/OU=emSign PKI/O=eMudhra Technologies Limited/CN=emSign ECC Root CA - G3' \
    -v second='=== /C=GB/ST=Greater Manchester/L=Salford/O=Comodo CA Limited/CN=AAA Certificate Services' \
    '/^(===|###) / { omit=($0==first || $0==second) } !omit' \
    /etc/ssl/cert.pem > "$tls_tmp" && [ -s "$tls_tmp" ]; then
    sudo /usr/bin/install -m 0644 -o root -g wheel "$tls_tmp" /etc/ssl/cert.pem
else
    printf 'STOP: 一時ファイルを作れませんでした。変更せず相談してください。\n'
fi
/bin/rm -f "$tls_tmp"
~~~

エラーがあれば止めます。A-2の一覧化コマンドをもう一度実行し、2つの名前が出ないことと解析エラーがないことを確認します。
名前が残る場合は、説明行の形式が異なる可能性があります。自己判断で削除条件を広げません。

### A-4．必ず再検査

手順6を再実行します。正常接続ができ、問題の2経路を証明書エラーで拒否できて初めて、そのツールは合格です。
Homebrew等のツールに合格結果をそのまま流用しません。

この暫定変更はmacOSの更新で上書きされることがあります。Apple側の正式対策が行き渡るまでは、macOS更新後に手順6を再確認します。
何も確認せず、古いバックアップを更新後のシステムへ戻してはいけません。

変更直後に正常なサイトが利用できなくなり、先生・管理者が復元を判断した場合のコマンド：

~~~sh
sudo cp -p /etc/ssl/cert.pem.stackchan-20261025.bak /etc/ssl/cert.pem
~~~

復元すると今回の問題に対する暫定対策も戻るため、そのツールで開発を再開せず、別の対策を管理者と相談します。

## 付録B．この証明書対策で変更しないもの

platformio.iniのM5ライブラリ版、ボード指定、書き込み速度、SPIFFS指定は変更しません。
既存の「Mac専用マニュアル読み替え表.md」には授業版の固定設定と異なる設定例があります。今回の証明書対策のために、そのテンプレートでplatformio.iniを置き換えないでください。
本体への書き込みと本体テストは別の作業です。WindowsのCOM番号やPowerShellのログ取得を、そのままMacで使わないでください。
