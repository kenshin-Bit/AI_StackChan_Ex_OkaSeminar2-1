# PCごとの安全対策マニュアル（先生用・Windows）

作成日：2026-10-25。翌10月26日に、別のPCで再開するための手順です。
既にVS Code・Git・PlatformIOを導入したWindows PCが対象です。証明書の手動削除は行いません。

## 0．明日の順序とPCごとの記録

1. この文書の手順1〜7で、そのPCの開発環境を対策する。
2. 手順8で、今日修正したプログラムを別PCへ移す。
3. [本体の書き込み・テスト手順](20261025_Gemini証明書対策.md)へ進む。
4. 先生の実機確認と学生のPC確認を終えてから、学生への再開指示を判断する。

PCの対策は1台ずつ必要です。同じPCでも別アカウント・別のPython環境なら追加確認が必要です。プロジェクトのコピーだけでは引き継がれません。

|---|---|---|---|---|---|---|---|

対象はWindows・Git・PlatformIOです。Node.js、Conda、WSL、Docker、別のPython、アプリ同梱のGit等を開発に使う場合は、それぞれ追加確認します。この文書だけでPC上の全アプリの安全を保証するものではありません。

## 1．対策完了まで止める作業

演習のBuild・Upload・Upload Filesystem、Gitのclone・pull・fetch・push、通常の部品追加・更新を一旦止めます。
PlatformIOはビルド時に不足部品を自動取得することがあるためです。
本体の音声対話は、本体の修正・実機確認が済むまで待ちます。

以下に指定する安全対策の更新と公開先への接続検査は実施できます。
コード・性格設定の編集、ローカル保存、資料閲覧、レポート作成は続けられます。
環境やファイルを削除する必要はありません。

## 2．Windows・ブラウザ・VS Codeを更新する

1. 作業中のファイルを保存する。
2. 「設定」→「Windows Update」→「更新プログラムのチェック」で通常の更新を適用する。
3. 求められたら再起動する。
4. Chromeの「ヘルプ」→「Google Chromeについて」、またはEdgeの「ヘルプとフィードバック」→「Microsoft Edgeについて」で更新し、ブラウザを再起動する。
5. VS Codeも「ヘルプ」内の更新確認から公式更新を適用する。

学校管理PCで更新できない場合は管理者へ依頼します。ここだけではGit・Pythonの対策は完了しません。

## 3．Git for Windowsを更新する

1. VS Code、Git Bash、GitHub Desktopなど、Gitを使うアプリを閉じる。
2. 更新したブラウザで[公式リリース](https://github.com/git-for-windows/git/releases/tag/v2.56.0.windows.3)を開く。
3. Assetsから、通常のIntel/AMDの64ビットPCでは「Git-2.56.0.3-64-bit.exe」を取得する。ARMのPCはARM64版。
4. 実行し、既存設定を引き継いで更新する。アンインストールは不要。
5. 新しくPowerShellを開き、次を実行する。

~~~powershell
git --version
where.exe git
~~~

合格：git version 2.56.0.windows.3、または後継の修正版。
古い版が出る、複数の別のGitが見つかる場合は未確認として相談します。
GitHub Desktop等に同梱される別のGitは、この更新だけで対策済みとは扱いません。そのアプリも公式更新し、授業では確認済みのGitを使います。

## 4．PlatformIOが使うPythonを調べる

VS CodeのPlatformIOアイコン→Quick Access→Miscellaneous→PlatformIO Core CLIを開きます。
見つからなければCtrl+Shift+Pで「PlatformIO: Open PlatformIO Core CLI」を検索します。
開いたターミナルで実行します。

~~~text
pio system info
~~~

「Python」の版と「Python Executable」のパスを控えます。ビルドはしません。
Python Executableは、例えば C:\Users\ユーザー名\.platformio\penv\Scripts\python.exe です。
例ではなく、自分のPCに表示されたパスを使います。

Pythonが3.10以上なら続けます。3.9以下、コマンドが動かない、パスが見つからない場合は止めて相談します。

## 5．そのPythonのpip・certifiを対策する

スタートメニューから通常のPowerShellを開きます。管理者権限は不要。
ここから同じPowerShell画面で進めます。閉じた場合は変数設定をやり直します。

~~~powershell
$pioPython = Read-Host "Python Executableのパスを引用符なしで貼り付けてEnter"
& $pioPython --version
& $pioPython -m pip --version
~~~

入力待ちになったら、手順4のpython.exeまでのパスを貼り付けてEnterを押します。
pipは部品を取得する道具、certifiは接続先確認用の証明書一覧です。

### 5-1．pipが26.2.2未満の場合だけ更新

26.2.2以上なら、この長いコマンドは飛ばして5-2へ進みます。新しいpipを古い版へ戻さないためです。
26.2.2未満なら、次を1行丸ごとコピーして実行します。末尾のSHA-256で取得ファイルの一致を確認します。

~~~powershell
& $pioPython -m pip install "pip @ https://files.pythonhosted.org/packages/3f/06/3e4420302363fbb71be3c7f35ce042f54bfca330e3e66b3a2e3c4cca579f/pip-26.2.2-py3-none-any.whl#sha256=fd7f4dfa8190e014013b9f08f3e973f4e4c26ffd179a204895533a7254813a70"
~~~

エラーなら止めます。ハッシュ不一致を無視したり、--trusted-host等を追加したりしません。

### 5-2．certifiを更新・結果確認

pipの更新成功を確認してから実行します。

~~~powershell
& $pioPython -m pip install --upgrade "certifi>=2026.10.19"
& $pioPython -m pip --version
& $pioPython -c "import certifi; print(certifi.__version__)"
~~~

合格：pipが26.2.2以上、certifiが2026.10.19以上。
失敗時は最後の数行を相談します。Python環境を削除・再作成したり、pio pkg updateを実行したりしません。
別のPythonも授業で使う場合は、その実行ファイルを$pioPythonに指定して手順5以降を繰り返します。

## 6．正常接続と証明書の拒否を確認する

公開サイトへの検査です。APIキー・パスワード・トークンは不要です。
問題の証明書を使う代表的な2経路を検査します。全攻撃の網羅試験ではありません。
名前解決失敗・時間切れは「未確認」で、証明書拒否の合格とは区別します。

### 6-1．Windows付属curl

~~~powershell
& "$env:WINDIR\System32\curl.exe" -I https://github.com/
~~~

HTTP/2 200などのHTTP応答が返ることを確認します。続けて次の2つを実行します。

~~~powershell
& "$env:WINDIR\System32\curl.exe" https://dv-g3b-emudhra.we-have-a-problem.com/
& "$env:WINDIR\System32\curl.exe" https://dv-g3b-aaa-emudhra.we-have-a-problem.com/
~~~

この2つは、証明書の理由で失敗するのが合格です。
例：CERT_E_REVOKED、certificate revoked、証明書チェーンを信頼できない旨のエラー。
ページ本文を取得できた場合は止めます。-k、--insecure、--ssl-no-revokeは使いません。

### 6-2．実際に使うGit

エクスプローラーで、firmwareの一つ上のプロジェクトフォルダーを開き、アドレス欄のパスをコピーします。

~~~powershell
$projectRoot = Read-Host "プロジェクトのルートのパスを引用符なしで貼り付けてEnter"
Set-Location -LiteralPath $projectRoot
git ls-remote https://github.com/git/git.git HEAD
~~~

通常接続では長い英数字とHEADの表示が合格です。ログインを求められたら入力せず相談します。
続けて次を実行します。

~~~powershell
git ls-remote https://dv-g3b-emudhra.we-have-a-problem.com/ HEAD
git ls-remote https://dv-g3b-aaa-emudhra.we-have-a-problem.com/ HEAD
~~~

この2つは証明書エラーで失敗するのが合格です。
repository not foundやHTTP 404だけなら、証明書を拒否した証拠ではありません。未確認として止めます。

### 6-3．PlatformIOのPythonが使う通信

以下を一塊で同じPowerShellへコピーします。実際に使うrequestsで検査します。

~~~powershell
@'
import requests
urls = [
    ('https://github.com/', False),
    ('https://dv-g3b-emudhra.we-have-a-problem.com/', True),
    ('https://dv-g3b-aaa-emudhra.we-have-a-problem.com/', True),
]
passed = 0
for url, must_reject in urls:
    try:
        r = requests.get(url, timeout=20, allow_redirects=False)
    except requests.exceptions.SSLError as exc:
        detail = str(exc).lower()
        ok = must_reject and 'certificate verify failed' in detail.replace('_', ' ')
        result = 'certificate rejected' if ok else 'other TLS error: not confirmed'
    except requests.exceptions.RequestException:
        ok = False
        result = 'network error: not confirmed'
    else:
        ok = not must_reject and 200 <= r.status_code < 400
        result = 'HTTP ' + str(r.status_code)
        r.close()
    print(('PASS' if ok else 'STOP'), url, result)
    passed += int(ok)
raise SystemExit(0 if passed == len(urls) else 1)
'@ | & $pioPython -
~~~

合格：3行ともPASS。STOPやrequestsが見つからない等のエラーなら未確認です。
検証を無効にせず相談します。

## 8．今日の修正版を別のPCへ移す

今日の変更はGitへコミット・pushしていません。明日git pullするだけでは取得できません。
このPCの my_doc/20261025_証明書対策_持ち出し.zip をUSBメモリ等で持ち出します。

1. ZIPをプロジェクトとは別の一時フォルダーへ展開する。
2. ZIP内の「はじめに.md」と「SHA256SUMS.txt」を確認する。
3. 別PCの既存プロジェクトを、そのPC内でバックアップする。個別の変更があるファイルは比較して取り込む。
4. ZIPのファイルを同じ相対位置へ配置する。特に次の2ファイルがプログラムの修正本体です。
   - firmware/src/llm/Gemini/GeminiLive.cpp
   - firmware/src/rootCA/rootCAgoogleGemini.h
5. my_scriptとdocの添付ファイルも同じ位置へ配置する。既に同じ変更を同期済みなら二重の上書きは不要。
6. 同じPowerShellで、修正版を確認する。

~~~powershell
Select-String -LiteralPath firmware/src/llm/Gemini/GeminiLive.cpp -Pattern 'webSocket.beginSslWithCA'
Select-String -LiteralPath firmware/src/rootCA/rootCAgoogleGemini.h -Pattern 'SHA-256'
& $pioPython -B my_script/check_gemini_tls.py
~~~

最後の検査がすべてPASSなら、[本体の書き込み・テスト手順](20261025_Gemini証明書対策.md)へ進みます。
これはPC上の本体用CA検査で、本体自体の検査ではありません。

ZIPにはAPIキー・Wi-Fi設定、firmware/data/、.pio、完成済みバイナリを含めません。
別PCではソースからビルドします。本体に既存の設定がある場合、今回のためのuploadfsは不要です。

## Mac・LinuxのPC

Macは[Mac学生向けの安全対策マニュアル](20261025_PC安全対策_Mac学生用.md)を使います。
更新・PlatformIOのPython・使用中のGitとcurlの接続検査を説明し、標準ツールに問題が残る場合のApple公式案内に基づく暫定策を付録に載せています。
システムの証明書一覧の変更は、先生・管理者が対象Macを確認して行います。Mac実機では未検証なので、最初の少数例で手順と結果を確認します。
Homebrew等の別のツールは独自の確認が必要です。
LinuxはOS・ブラウザの公式更新と環境の記録を行い、個別確認へ回します。このWindows版のコマンドは流用しません。

## 困ったとき

OS、Git・Python・pip・certifiの版、PASSかSTOPかを伝えます。パス中のユーザー名は伏せて構いません。
SC_SecConfig.yaml、APIキー、Wi-Fiパスワード、生のシリアルログは送らないでください。
