# Gemini Live の証明書確認（2026-10-25）

## 何を直したか

GeminiLive.cpp の beginSSL（検証省略）を beginSslWithCA に変更した。
rootCAgoogleGemini.h に Google 公式配布の GTS Root R1〜R4 を格納した。
秘密情報や設定yamlの変更は不要。M5ライブラリ固定版、SPIFFS、音声再生、APIの形式は変更しない。

旧ヘッダの証明書は名前・有効期限は GTS Root R1 だったが、DERのSHA-256は
2A575471E31340BC21581CBD2CF13E158463203ECE94BCF9D3CC196BF09A5472
で、公式R1の D947432ABDE7B7FA90FC2E6B59101B1280E0E1C7E4E40FA3C6887FFF57A7F4CF と異なった。
過去の検証失敗の原因候補であり、当時の実機エラーの原因確定とは区別する。

取得元: https://pki.goog/repository/ 、 https://pki.goog/repo/certs/gtsr1.pem （r2/r3/r4も同形式）。
4証明書のDERのSHA-256はヘッダと検査スクリプトに記録している。

## 接続できない場合

本体は起動時に既存のNTP処理で時刻を取得する。時刻が未取得で証明書が有効期間外と判断された場合、TLS接続は失敗する。NTPはバックグラウンドで継続し、既存のWebSocket再試行で再接続する。
GoogleのCA、接続先名、有効期限の検証を無効にするフォールバックは作らない。
NTPは通常の時刻取得であり、認証された時刻配信ではない。別途の機能としてオンラインCRL/OCSP検査を追加するものでもない。
テザリングの接続と時刻同期を確認する。TLSが成立した後の無応答・切断は、AGENTS.mdどおり無料枠の使用状況を先に確認する。

## PC上の検査

PowerShellでプロジェクトのルートから、使用中のPythonで次を実行する。

    python my_script/check_gemini_tls.py

Python標準ライブラリとOpenSSLを使う。WindowsではGit付属OpenSSLも自動検出する。
公式CAの指紋・自己署名、GoogleへのTLS接続、接続先名不一致、未設定時刻、期限切れ、信頼しない自己署名証明書の拒否を確認する。APIキーを送らず、音声APIの無料枠を消費しない。
この検査はPCのOpenSSLによるもので、ESP32の実機検証を代替しない。

## 明日の入口

最初に[PCごとの安全対策マニュアル](20261025_PCごとの安全対策_先生用.md)を実施します。
別PCでは、今日の修正版を移す作業も必要です。Gitへ未送信の変更はgit pullでは取得できません。
学生への案内は[学生用暫定版](20261025_PC安全対策_学生用_暫定版.md)を使います。

## 本体への反映（先生の実機確認用）

### 1．作業フォルダーとPythonを指定する

PCの対策と修正版の取り込みが終わってから進めます。
通常のPowerShellで、実際の場所を入力します。途中で画面を閉じたら、この設定からやり直します。

~~~powershell
$projectRoot = Read-Host "firmwareの一つ上のプロジェクトのパスを引用符なしで入力"
Set-Location -LiteralPath $projectRoot
$pioPython = Read-Host "pio system infoのPython Executableを引用符なしで入力"
& $pioPython -m platformio --version
~~~

以下では実際のPythonからPlatformIOを起動します。pio.exeの配置がPCごとに違っても、確認済みのPythonを使えます。

### 2．修正版をビルドしてログパッチを適用する

~~~powershell
& $pioPython -m platformio run -d firmware -e m5stack-cores3-realtime
~~~

最後にSUCCESSと出ることを確認します。初回は部品の取得に時間がかかります。
失敗した場合は、ライブラリ版を変えず、エラーを相談します。

成功後、既存の切断理由ログパッチを適用し、もう一度ビルドします。

~~~powershell
powershell -ExecutionPolicy Bypass -File my_script\patch_websockets_close_log.ps1
& $pioPython -m platformio run -d firmware -e m5stack-cores3-realtime
~~~

2回目もSUCCESSを確認します。パッチが適用済みなら変更されなくて構いません。

### 3．本体を接続・COM番号を確認する

本体を十分充電し、データ通信できるUSBケーブルで接続します。VS Code等のシリアルモニターを閉じます。

~~~powershell
Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match 'COM\d+' } | Select-Object Name
~~~

Bluetoothではなく「USB シリアル デバイス」のCOM番号を選びます。
見つからない場合はケーブル・接続を確認し、推測の番号で書き込まないでください。

~~~powershell
$port = Read-Host "本体のCOM番号を入力（例 COM5）"
~~~

### 4．プログラムだけを書き込む

~~~powershell
& $pioPython -m platformio run -d firmware -e m5stack-cores3-realtime -t upload --upload-port $port
~~~

最後のSUCCESSを確認します。固定の書き込み速度460800は上げません。
今回はプログラム修正なのでuploadです。既に本体に設定が入っており、Wi-Fiや性格を変えない場合はuploadfs不要です。

別PCでも、本体内の設定は残ります。スマホのテザリング名・パスワードが以前と違う場合や、新品の本体なら別途設定が必要です。
その場合はローカルのSC_SecConfig.yaml等を確認してからuploadfsへ進みます。uploadfsはdata全体を上書きするので、今回の手順に便乗して実行しないでください。
APIキー・Wi-Fiパスワードの中身をチャットへ送る必要はありません。

### 5．起動ログと時刻・接続を確認する

スマホのテザリングを有効にし、次の手順で20秒の起動ログを取得します。
AGENTS.md指定の取得処理を使います。COM番号だけ上で入力したものを渡します。
生ログは秘密情報を含むので、Git管理外のLocalAppDataへ保存し、画面には指定の除外フィルターを通した結果だけ出します。

~~~powershell
$p = New-Object System.IO.Ports.SerialPort $port,115200
$p.ReadBufferSize = 262144; $p.ReadTimeout = 300; $p.DtrEnable = $false
$p.Open(); $p.RtsEnable = $true; Start-Sleep -Milliseconds 150; $p.RtsEnable = $false
$sb = New-Object System.Text.StringBuilder
$end = (Get-Date).AddSeconds(20)
while ((Get-Date) -lt $end) { try { [void]$sb.Append($p.ReadExisting()) } catch {}; Start-Sleep -Milliseconds 60 }
$p.Close()
$logDir = Join-Path $env:LOCALAPPDATA 'StackchanLogs'
New-Item -ItemType Directory -Force -Path $logDir | Out-Null
$logPath = Join-Path $logDir ("boot-" + (Get-Date -Format 'yyyyMMdd-HHmmss') + ".log")
[IO.File]::WriteAllText($logPath, $sb.ToString(), [Text.UTF8Encoding]::new($false))
$sb.ToString() -split "\n" | Where-Object { $_ -notmatch 'password|Bearer|sk-|AIza|AQ\.|x-goog|[?]key=|Key:|SSID' }
~~~

合格の目安：
- NTPの表示時刻が実際の日付・時刻と大きくずれていない。
- setupCompleteが出る。
- 本体がタップして会話できる待機状態になる。

20秒で接続が終わらない場合は未確認です。無出力なら取得側のCOM占有・接続を疑います。
生ログやそのファイル自体は共有しません。相談には必要な行だけを使い、秘密情報が残っていないか人が確認します。
ここでsetupCompleteが出れば、修正版ではGoogleとのTLS確認を通過してWebSocketのセットアップに進めたことを確認できます。

### 6．音声対話を3往復確認する

上の取得処理が終わりCOMを閉じたことを確認してから操作します。

1. 画面をタップし、短く「こんにちは」と話す。
2. もう一度タップして録音を終え、返事を待つ（既存の操作と同じ）。
3. 返事が聞こえたら、次の質問をする。同様に3往復確認する。
4. 音が極端に早口・ギザギザにならないこと、タッチ・画面・首の動作を確認する。

会話が終わらない、無音、切断が続く場合は、コードを推測で変更する前に[Gemini無料枠の使用状況](https://aistudio.google.com/app/usage)を確認します。
TLSの証明書エラー、時刻未取得、無料枠の問題は区別して記録します。課金は有効化しません。

### 7．テザリングOFF→ONを確認する

1. 本体が会話できている状態で、スマホのテザリングをOFFにする。
2. 会話中なら切断の表示を確認する。録音が勝手に再開しないことを確認する。
3. テザリングをONへ戻す。
4. Wi-Fi再接続は10秒ごとの処理なので、直後に反応しなくても少し待つ。
5. 待機状態へ戻ったら、タップして短い会話をもう1回行う。

戻らなければ未確認として記録し、検証省略へ戻して回避しません。

### 8．記録と学生への再開判断

~~~text

~~~

この文書の通常動作テストだけでは、実機で不正証明書を拒否したという実測結果にはなりません。
実機の拒否検査は、APIキーを使わない専用のTLS検査で別途行います。現時点では専用検査用ファームウェアは添付していません。
本番の認証URLを偽サイトへ向けたり、APIキーを使って検査したりしないでください。
最終的な学生向け手順の確定・全員への再開指示の前に、未検証項目を確認します。

## 確認結果

- PC検査: 4ルートの公式指紋・自己署名、GoogleへのTLS接続、ホスト名不一致・未設定時刻・期限切れ・自己署名の拒否、すべて成功。
- CoreS3 realtime: 切断ログパッチ適用後の最終ビルド成功（RAM 72,792 bytes、Flash 2,501,065 bytes）。firmware/.pio/build/m5stack-cores3-realtime/firmware.bin を生成。4ルートの組み込みも確認済み。
- 実ライブラリ確認: WebSocketsのbeginSslWithCA→setCACert→WiFiClientSecureのMBEDTLS_SSL_VERIFY_REQUIRED、mbedtls_ssl_set_hostnameを確認。ESP32-S3のMBEDTLS_HAVE_TIME_DATEも有効。
- 旧証明書: PC OpenSSLの自己署名検査は成功した。公式の同名ルートとの指紋不一致だけから、過去のエラー原因や改変経緯を断定しない。
- 実機: ユーザーの指示により今回は修正とビルドまでで終了。本体への書き込み、音声対話、Wi-Fi復帰、実機での不正証明書拒否は未実施。
- 対象外: Core2/AtomS3Rのビルド、Gemini以外のサービスの通信、PCに入っている他の開発環境の安全確認。
